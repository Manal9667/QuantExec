# Market Data Format and Schema (Phase 1)

## Overview

This document specifies the CSV market data format consumed by `CsvMarketSource` and produced by external adapters. All data is normalized into the `MarketState` structure before reaching the matching engine or execution strategies.

## Required CSV Schema

A valid CSV file must include these **required columns** (in any order):

```
timestamp_ms, last, bid, ask, bid_size, ask_size, volume
```

### Required Columns

| Column | Type | Unit | Description |
|--------|------|------|-------------|
| `timestamp_ms` | uint64 | milliseconds | Time since epoch (Unix timestamp). Must be **strictly increasing** (no duplicates, no backward steps). |
| `last` | double | currency | Last trade price. Must be positive and finite. |
| `bid` | double | currency | Best bid price. Must be positive and finite. |
| `ask` | double | currency | Best ask price. Must be positive and finite. |
| `bid_size` | uint64 | quantity | Volume available at the best bid. Must be non-negative. |
| `ask_size` | uint64 | quantity | Volume available at the best ask. Must be non-negative. |
| `volume` | uint64 | quantity | Cumulative total volume for the symbol (session open). Must be non-negative. |

### Validation Rules for Required Columns

1. **Timestamp monotonicity**: `timestamp_ms` must strictly increase. Duplicate or backward timestamps are rejected.
2. **Price finiteness**: `last`, `bid`, `ask` must not be NaN or infinity.
3. **Bid-ask relationship**: `bid ≤ ask`. If `bid > ask`, the row is invalid.
4. **Positive prices**: All prices must be `> 0.0`.
5. **Quantities**: `bid_size`, `ask_size`, `volume` must be non-negative (`>= 0`).

## Optional Columns

### `bar_volume` (optional)

| Column | Type | Unit | Description |
|--------|------|------|-------------|
| `bar_volume` | uint64 | quantity | Volume accumulated during this event / bar only. Defaults to 0 if omitted. |

**Use case**: VWAP strategy can use `bar_volume` to weight slices to the market's volume profile within a timeframe.

### Depth Columns (optional)

| Column | Type | Format | Description |
|--------|------|--------|-------------|
| `bid_depth` | string | `price:qty\|price:qty\|...` | Multiple bid levels, best first. |
| `ask_depth` | string | `price:qty\|price:qty\|...` | Multiple ask levels, best first. |

**Format**: Pipe-delimited (`|`) levels; each level is `price:qty`.

**Example**:
```
bid_depth: 100.0:100|99.99:200|99.98:150
ask_depth: 100.01:50|100.02:200|100.03:300
```

**Parsing**:
- If `bid_depth` is present, it is parsed into a vector of `BookLevel` objects.
- The first level (best) becomes the top-of-book bid; subsequent levels are stored for matching.
- If parsing fails for any level, that level is skipped; incomplete depth is accepted.
- If no depth columns are present, only top-of-book (`bid`, `ask`, `bid_size`, `ask_size`) is available.

## Complete Example

```csv
timestamp_ms,last,bid,ask,bid_size,ask_size,volume,bar_volume,bid_depth,ask_depth
1000,100.01,100.0,100.02,212,579,120,120,100.0:212|99.99:425,100.02:579|100.03:414
2000,99.99,99.98,100.0,252,546,359,239,99.98:252|99.97:756,100.0:546|100.01:579
3000,99.97,99.96,99.98,416,216,416,57,99.96:416|99.95:347,99.98:216|99.99:411
```

## Data Provenance

### Phase 1: Synthetic Data Only

The sample dataset (`datasets/sample_synthetic.csv`) is **deterministic and synthetic**. It is generated by `datasets/generate_sample.py` and is used for:

- Reproducible testing
- Example configurations
- Validating the execution pipeline

**It does NOT represent real market data.**

### Alpaca Historical Data (Noted Limitation)

The codebase contains stubs for Alpaca historical data adapters (`python/alpaca_historical.py`, `python/alpaca_adapter.py`). These are **not functional in Phase 1** and are documented as limited by:

1. **Alpaca API restrictions**: Historical data returned is aggregated (daily OHLCV bars or 1-minute candles), not tick-by-tick.
2. **No intrabar trades**: Alpaca does not provide individual trade records within a bar; only the bar's OHLCV summary is available.
3. **Last price ambiguity**: The "close" price of a bar is used as `last`; it is not the true last trade.
4. **No order book depth**: Alpaca historical data does not include order book snapshots or depth information.

**For Phase 1, do not use Alpaca historical adapters.** Use the synthetic dataset or implement a custom CSV parser for your own data source.

## Market Data Normalization

The function `normalize_market_state(MarketState& state)` is applied to every record after parsing:

1. If `mid_price <= 0` and `bid > 0` and `ask > 0`, derive `mid_price = (bid + ask) / 2`.
2. If `last_price <= 0`, set `last_price = mid_price`.
3. If `bids` vector is empty but `bid > 0` and `bid_size > 0`, add a single level `{bid, bid_size}` to `bids`.
4. If `asks` vector is empty but `ask > 0` and `ask_size > 0`, add a single level `{ask, ask_size}` to `asks`.
5. Sync top-of-book: if `bids` is non-empty, set `bid = bids[0].price` and `bid_volume = bids[0].qty`.
6. Sync top-of-book: if `asks` is non-empty, set `ask = asks[0].price` and `ask_volume = asks[0].qty`.
7. If `mid_price` is still `<= 0` and `last_price > 0`, set `mid_price = last_price`.

## Validation and Error Handling

### File-Level Errors

| Error | Behavior | `CsvMarketSource::ok()` |
|-------|----------|----------------------|
| File not found | Load fails silently | Returns `false` |
| Empty file | No rows to read | Returns `false` |
| Malformed header | Required column missing | Returns `false` |

### Row-Level Errors

| Error | Behavior | Recovery |
|-------|----------|----------|
| Malformed numeric field | Exception caught; all states cleared | Returns `false` |
| Duplicate timestamp | Timestamp check during sort | Rejected (backward timestamps already rejected) |
| Invalid bid/ask | Not explicitly checked after parse; may pass validation | Undefined behavior (should be rejected) |
| Negative price/quantity | May pass parsing; not all cases validated | Partial validation; see Issue #X |
| Non-monotonic timestamps | Sorted after load; original order lost | Data permuted silently |

### Recommended Handling

When `CsvMarketSource::ok()` returns `false`:

```cpp
CsvMarketSource source("datasets/sample_synthetic.csv");
if (!source.ok()) {
    std::cerr << "Failed to load market data. Check:\n"
              << "  - File exists: datasets/sample_synthetic.csv\n"
              << "  - Required columns present: timestamp_ms, last, bid, ask, ...\n"
              << "  - All rows have valid numeric values\n"
              << "  - Prices are finite and non-negative\n"
              << "  - Timestamps are monotonically increasing\n";
    return 1;
}
```

## Limitations in Phase 1

### Full L2/L3 Depth Not Available

- Depth is limited to what's in the CSV (typically 2 levels).
- True order book reconstruction from tick data is not supported.
- For multi-level analysis, extend the CSV schema and `BookLevel` structures (not Phase 1 scope).

### No Trade-by-Trade Tick Data

- Each CSV row represents a market event or bar, not individual trades.
- Trade prices and quantities are inferred from bar midpoints and volumes.
- True trade-by-trade execution simulation requires a different data model (not Phase 1 scope).

### Volume Interpretation

- `volume` is cumulative session volume, not incremental bar volume.
- `bar_volume` (optional) is the incremental volume for this bar/event only.
- The matching engine does not enforce volume constraints; it matches against submitted limit orders.

### Timestamp Units

All timestamps are in **milliseconds since Unix epoch**. Sub-millisecond precision is not supported. If your data is in seconds or microseconds, convert before loading:

```python
# Convert from seconds to milliseconds
df['timestamp_ms'] = (df['timestamp_sec'] * 1000).astype(int)

# Convert from microseconds to milliseconds
df['timestamp_ms'] = (df['timestamp_us'] // 1000).astype(int)
```

## How to Generate / Provide Your Own Dataset

### 1. Prepare CSV with Required Columns

```python
import pandas as pd

# Load or generate your data
df = pd.DataFrame({
    'timestamp_ms': [1000, 2000, 3000, ...],
    'last':         [100.01, 99.99, 99.97, ...],
    'bid':          [100.0, 99.98, 99.96, ...],
    'ask':          [100.02, 100.0, 99.98, ...],
    'bid_size':     [212, 252, 416, ...],
    'ask_size':     [579, 546, 216, ...],
    'volume':       [120, 359, 416, ...],
})

# Save
df.to_csv('datasets/my_data.csv', index=False)
```

### 2. (Optional) Add Depth Information

```python
# Create depth columns as pipe-delimited strings
df['bid_depth'] = df.apply(lambda r: f"{r['bid']}:{r['bid_size']}|{r['bid']-0.01}:{r['bid_size']//2}", axis=1)
df['ask_depth'] = df.apply(lambda r: f"{r['ask']}:{r['ask_size']}|{r['ask']+0.01}:{r['ask_size']//2}", axis=1)

df.to_csv('datasets/my_data.csv', index=False)
```

### 3. Validate

```python
from executor import CsvMarketSource

source = CsvMarketSource('datasets/my_data.csv')
if source.ok():
    print("Data loaded successfully")
else:
    print("Data load failed; check schema and values")
```

### 4. Run Experiment

```bash
# Update configs/example_experiment.yaml
sed -i 's|datasets/sample_synthetic.csv|datasets/my_data.csv|' configs/example_experiment.yaml

python3 python/run_experiment.py configs/example_experiment.yaml
```

## Reproducibility

**All data sources (CSV, synthetic, vector) produce deterministic results when replayed.** There is no randomness in the Phase 1 pipeline:

- ✓ Market data is fixed
- ✓ Strategies (TWAP, VWAP) are deterministic
- ✓ Matching engine is deterministic
- ✓ Cost model is deterministic

**Replaying the same dataset + config twice produces identical `ExecutionResult`.**
