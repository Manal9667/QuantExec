## 2. Commands run, in order

```bash
# Configure + build (Release)
mkdir -p build && cd build
cmake -DCMAKE_BUILD_TYPE=Release -Dpybind11_DIR="$(python3 -c 'import pybind11; print(pybind11.get_cmake_dir())')" ..
cmake --build . --config Release -j"$(nproc)"

# C++ tests
ctest --output-on-failure

# Backend tests
cd ..
python3 -m unittest discover -s backend/tests -v

# Frontend build
cd frontend
npm install
npm run build

# Determinism check (run the same experiment twice)
cd ..

PYTHONPATH=build python3 python/run_experiment.py configs/example_experiment.yaml > run2.log
diff run1.log run2.log
```

### 3.3 Frontend build (`npm run build`)

The delivered `frontend/node_modules` was built for a different platform
(Rollup's native optional dependency didn't match this machine, a known
npm/Rollup optional-dependency issue). Fix applied: `rm -rf node_modules
package-lock.json && npm install`, then `npm run build` succeeded:


**Action item carried into later steps:** commit a fresh `package-lock.json`
generated on a clean checkout, or document in the README that
`node_modules` must never be committed/shipped and `npm install` must be run
per-machine. Shipping a platform-specific `node_modules` (as the uploaded
archive did) is itself a reproducibility bug.
